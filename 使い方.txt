 SyncCheck ― 2カメのズレを測る
════════════════════════════════════════════════════════

■ 何をするもの

2台のカメラで撮った同じ場面の「音のズレ」を測る。
編集ソフトで2本を重ねるとき、何秒ずらせば合うかを出す。

**動画はこの端末から出ない。** ブラウザの中で音声だけを読んで
計算する。アップロードは発生しない。


■ SemiCut とどう違う

SemiCut は「切って・重ねて・書き出す」まで全部やる道具。
SyncCheck は**測るだけ**。別のプログラムとして作った。

  SemiCut    … カット・合成・書き出しまで。PC で python serve.py を動かす
  SyncCheck  … ズレを測るだけ。ブラウザだけで動く。iPad でも使える

同期の計算部分は SemiCut から移植している（実測で確かめた判断が
入っているため）。ただしファイルは別で、直しても互いに影響しない。


■ 途中で切れて再開した素材に対応している

これがこのアプリを作った理由。

2カメでも、録画を止めて再開すると

    A側: A1.mp4  A2.mp4  A3.mp4
    B側: B1.mp4  B2.mp4  B3.mp4

のように何本にも分かれる。**再開するたびにズレ方が変わる**ので、
1組目で測った値を他の組に当てはめると全部ずれる。

SyncCheck は撮影時刻から「どの組が重なっているか」を自動で見つけ、
**組ごとに別々に測る**。


────────────────────────────────────────────────────────
 使い方
────────────────────────────────────────────────────────

【このPCで使う】

    cd C:\dev\toolbox\SyncCheck
    python serve.py

ブラウザが開く（http://localhost:8770/）。

※ index.html をダブルクリックしても動かない。
   file:// ではブラウザが import 文を拒否するため。

【iPad で使う（同じ Wi-Fi から）】

PC でサーバーを立てて、iPad の Safari からそれを開く。

  1. PC と iPad を**同じ Wi-Fi** に繋ぐ
     （PC が有線でも、同じルーターにぶら下がっていればよい）

  2. PC で:

         cd C:\dev\toolbox\SyncCheck
         python serve.py --lan

     `--lan` を付けたときだけ外から見えるようになる。
     付けないと今までどおりこのPCからしか開けない。

  3. 初回は Windows の警告が出る。
     **「プライベート ネットワーク」にチェックを入れて「アクセスを許可」**。
     （パブリックは外さなくてよい）

  4. 画面に出た `iPad : http://192.168.x.x:8770/` を
     iPad の Safari に打ち込む。

  5. 終わったら PC のウィンドウで Ctrl+C。付けっぱなしにしない。

※ IP アドレスはルーターが配る番号なので、日が変わると変わることがある。
   毎回 `--lan` の起動時に表示されるので、そこを見る。

※ 開けないとき
   - PC と iPad が別の Wi-Fi（2.4GHz / 5GHz の別 SSID）になっていないか
   - ルーターの「プライバシーセパレータ」が ON だと端末同士が繋がらない
   - 3 の警告を「キャンセル」してしまった場合は、Windows の
     「セキュリティが強化された Windows ファイアウォール」→ 受信の規則 から
     python の規則を消して、もう一度 `--lan` で起動し直す

※ 初回だけ ffmpeg.wasm 約31MB のダウンロードが走る（LAN 内なのですぐ終わる）。
   2回目からはキャッシュされる。


【GitHub Pages に置く案について】

置けば URL だけで使えるが、**今は使えない**。
`dev-toolbox` リポジトリが private で、private リポジトリの Pages は
有料プランでないと使えないため。public にすると toolbox 全体が
公開されるので、そのためだけに切り替えない。

どうしても外から使いたくなったら、SyncCheck だけを別の public
リポジトリに切り出す。vendor/（ffmpeg.wasm）は Git に入っているので
そのまま動く。


【測る手順】

  1. A側（基準になるカメラ）の動画を放り込む。複数まとめてよい
  2. B側（合わせたいカメラ）の動画を放り込む
  3.「ズレを測る」を押す

出てくる数字の読み方:

    合わせるズレ +3.13秒
      → B側の映像を、編集ソフトのタイムライン上で
        3.13秒 後ろにずらすと合う
      → 負の値なら前にずらす

    内訳
      撮影時刻の差 … ファイルの日時から分かる差
      音で測った差 … 波形を突き合わせて分かった差
      合わせるズレ … この2つの合計。実際に使う値


────────────────────────────────────────────────────────
 出てくる印の意味
────────────────────────────────────────────────────────

  ■ ずれは一定（緑）

    問題なし。この値でそのまま合わせられる。

  ■ 区間ごとにズレが変わっている（黄）

    測った位置によってズレが違う。録画が途中で途切れている、
    フレームレートが安定していない、などが原因。
    1つの値では全体を合わせられないので、
    窓ごとの表を見て、区間を分けて合わせること。

  ■ 窓の過半数が一致しなかった・値を信用しないこと（赤）

    **この値は使わないこと。** 測れていない。
    音が似ている区間で誤検出している可能性が高い。
    編集ソフトで実際に波形を見て、手で合わせるほうが早い。

  ■ 短いので1回しか測っていない（黄）

    重なりが短く、複数の位置で検算できなかった。
    値は出ているが、確かめられていない。

【「重なる組が見つかりませんでした」と出る】

撮影時刻が失われている。クラウド経由でコピーしたり、
LINE や メールで送ったりすると日時が変わる。

  ・元のファイル（カメラから直接取り込んだもの）を使う
  ・USB で取り込んだ MOV は、Windows 側の日時が
    「録画開始」になることがある（実測で確認済み）。
    それでも SyncCheck は両方の可能性を試すので、たいてい通る

【「音声が入っていない素材があります」と出る】

音で測るアプリなので、音声トラックが無いファイルは測れない。
その素材を外して測ること。

【fcpxml が編集ソフトで開けない】

**実機未確認の部分。** このPCには Resolve も FCP も無いので、
実際に開けるかは確かめられていない。

開けなかったときは:

  ・fcpxml のフレームレートを、素材と同じものに変える
  ・「CSV で保存」して、秒数を見ながら手で合わせる
    （こちらは確実）

素材の場所はファイル名だけ書いてある。開いたあとに
「見つからない」と言われたら、素材を指定し直すこと。

【遅い】

ffmpeg.wasm はシングルスレッド版なので、ネイティブより遅い。
ただし読むのは音声だけ（映像は1フレームも読まない）なので、
1時間の動画でも数十秒で終わる。

  ・「測る長さ」を 60秒 にすると速くなる
  ・長くしても精度は大きく変わらない（180秒で十分）

【ファイル】

  index.html        画面
  src/sync.js       相互相関・多数決（SemiCut から移植）
  src/timeline.js   複数本を時間軸に載せて組を見つける
  src/audio.js      ffmpeg.wasm で音声を抜く
  src/measure.js    組ごとに測る
  src/export.js     テキスト / CSV / JSON / fcpxml の書き出し
  serve.py          ローカルで動かすための小さなサーバー
  vendor/           ffmpeg.wasm 一式（約31MB・Git に入れている）
  test/             検算

【消してはいけないコメント】

src/sync.js と src/timeline.js のコメントには、
実測で分かった判断が書いてある。読まずに直すと同じ穴に落ちる。

  ・**符号の導出**（D = LS - PS - lag）
    紙の上で決めると間違える。移植元で1度間違えて、
    正しい部品まで疑って半日つぶした。
    疑ったら測定点を変えて同じ答えになるか確かめること。

  ・**スコアではなく多数決で決める**
    セミナー音声は同じ部屋・同じ声で似た音が続くため、
    誤った位置のほうが高スコアになることが実際にある。
    このアプリのテスト素材でも起きた（20秒目の窓が
    +9.83秒で最高スコア。多数決で正しい +3.13 を採用）。

  ・**重なりが短い lag は見ない**（MIN_OVERLAP_RATIO = 0.5）
    重なり長で割って正規化しても、重なりが数秒まで減ると
    偶然そこだけ形が合って高スコアが出る。
    20秒の窓に探索幅15秒を与えたとき、
    正解(+3.13)より誤答(-13.59、重なり6秒)が高くなった。
    これは移植元には無かった修正。

  ・**concat してから -ss してはいけない**
    移植元で、複数本をつないでから頭出しすると
    4.069秒を頼んで 5.08秒 から返ってきた（1.01秒 late）。
    SyncCheck は必ず1本ずつ抜く。つなぐ処理を持たない。

  ・**更新日時の意味は取り込み経路で変わる**（素材23本の実測）
      mp4（スマホ）          更新日時 = 録画終了
      mov（iPad/LocalSend）  更新日時 = 録画終了
      MOV（iPad/USB）        更新日時 = 録画開始  ← これだけ違う
