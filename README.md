# SyncCheck

2台のカメラで撮った同じ場面の**音のズレを測る**だけのウェブアプリ。
編集ソフトで2本を重ねるとき、何秒ずらせば合うかを出す。

**→ https://nknknmp.github.io/synccheck/**

開くだけで使える。インストールも、サーバーも要らない。

## 動画はアップロードされない

外部へ通信するコードが1行も入っていない。ブラウザの中で音声だけを
読んで計算する。だから**圏外でも動く**（初回に一度開いておけば、
一式が端末に残る）。

## 何ができるか

- A側N本 / B側M本を放り込むと、撮影時刻から**重なる組を自動で見つける**
- **組ごとに別々にズレを測る**

録画を止めて再開すると、2カメでも素材が何本にも分かれる:

```
A側: A1.mp4  A2.mp4  A3.mp4
B側: B1.mp4  B2.mp4  B3.mp4
```

**再開するたびにズレ方が変わる**ので、1組目で測った値を他の組に
当てはめると全部ずれる。組ごとに測るのはこのため。

## 出先で使うとき

初回だけ ffmpeg 約31MB の読み込みが走る。**家の Wi-Fi で一度開いて
おく**こと。取り込みが終われば以降は通信しない。

Safari の共有ボタン →「ホーム画面に追加」でアプリのように開ける。

## 中身

- 同期の計算は音量の波形（8kHz モノラル）の相互相関で求めている
- 映像は1フレームも読まない（`-vn`）ので、1時間の動画でも軽い
- 音声のデコードに ffmpeg.wasm（単スレッド版）を使っている。
  `SharedArrayBuffer` が要らないので iPad Safari でも動く

詳しい使い方は [`使い方.txt`](使い方.txt)。

## 開発

```
python serve.py           # http://localhost:8770/
python serve.py --lan     # 同じ Wi-Fi の別端末から見る
```

`index.html` をダブルクリックしても動かない（`file://` では
ブラウザが `import` を拒否するため）。

テスト:

```
python test/sync_test.py     # 同期計算
python test/fcpxml_test.py   # 書き出し
```

`test/sw_check.html` と `test/offline_check.html` はブラウザで開く
（オフライン対応の確認）。

中身を直したら `sw.js` の `VERSION` を上げること。上げ忘れると
端末に残った古い版が出続ける。

## ライセンス

同梱の ffmpeg.wasm（`vendor/`）は各々のライセンスに従う。
